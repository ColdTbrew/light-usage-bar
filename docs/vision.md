# 프로젝트 목표와 범위

상태: 초안 · 작성일: 2026-10-25

## 해결하려는 문제

여러 AI 구독을 사용하면 남은 사용량과 초기화 시점을 확인하기 위해 각 앱이나 웹 화면을 반복해서 열게 된다. Light Usage Bar는 그 정보를 macOS 메뉴 막대에 모으되, 정보를 확인하지 않는 시간의 자원 비용을 작게 유지한다.

이 프로젝트의 우선순위는 **정확한 사용량 → 적은 상주 비용 → 빠르고 단순한 확인 경험 → 지원 범위 확대**다. 네 제공자를 모두 목표로 하되, 확인되지 않은 수치를 채워 넣어 지원을 완료한 것처럼 보이게 하지 않는다.

## 제품 범위

| 항목 | 결정 |
| --- | --- |
| 플랫폼 | macOS 전용. Windows는 고려하지 않는다. Linux도 현재 범위 밖이다. |
| 구현 언어 | Rust |
| 상세 화면 | GPUI |
| 메뉴 막대 | macOS 네이티브 상태 항목 |
| 지원 목표 | Claude, Codex, xAI 구독의 Grok Bot, Antigravity |
| 기본 동작 | 로그인한 제공자의 사용량을 읽고 로컬에 필요한 최소 상태만 유지 |
| 첫 측정 환경 | Apple Silicon Mac. Intel은 별도 검증 전까지 지원을 약속하지 않음 |
| 배포 | 공개 GitHub 저장소. 0.1.0 앱 패키지 후보 준비 중. 공개 산출물과 라이선스는 아직 없음 |

## 기본 경험

메뉴 막대 항목 하나를 클릭하면 활성화한 제공자의 현재 상태를 볼 수 있다. 첫 화면은 복잡한 차트보다 현재 사용률 또는 잔여량, 해당 한도 구간, 초기화 시점, 마지막 확인 시간을 우선한다.

제공자마다 한도의 의미가 다르므로 서로 다른 구독을 합친 하나의 전체 퍼센트를 만들지 않는다. 모델군별 한도가 있는 경우 제공자가 실제로 구분한 범위를 유지한다. 메뉴 막대에 노출할 대표 제공자나 간단한 상태 표시는 실제 응답 형태를 확인한 뒤 정한다.

패널을 열면 캐시를 즉시 표시한다. 값이 오래되었다면 갱신을 예약하고, 조회 중에도 마지막 성공 값과 그 시각을 확인할 수 있게 한다. 데이터가 최신인지 모르면서 최신 상태처럼 보이게 하지 않는다.

## 필수 요구사항

### 데이터의 의미와 신뢰도

- 구독 사용률, API 잔액, 로컬 활동 추정치를 서로 다른 정보로 취급한다.
- 값마다 출처와 조회 시각을 보관한다. 필요한 경우 서버가 보고한 갱신 시점도 구분한다.
- `조회 성공`, `오래된 캐시`, `인증 필요`, `조회 불가`, `지원 전`을 구분한다.
- 필드가 없다고 0%로 채우거나, 초기화 예정 시간이 지났다고 한도가 회복되었다고 단정하지 않는다.
- 100%를 초과한 사용량, 체험 계정, 팀 계정처럼 일반적인 개인 구독과 다른 응답을 손실 없이 다룬다.
- 표시 값은 실제 계정의 공식 화면과 대조한 뒤 해당 경로의 지원을 선언한다.

### 상주 비용

- 닫힌 패널을 위해 화면 갱신, 애니메이션, 짧은 주기의 이벤트 확인을 계속 실행하지 않는다.
- 비활성화한 제공자는 수집·타이머·자격 증명 읽기를 수행하지 않는다.
- 조회를 묶고 중복 실행을 막으며, 실패 시 재시도 간격을 늘린다.
- 절전 중 수집을 위해 시스템을 깨우지 않는다. 복귀 후 밀린 조회를 한꺼번에 실행하지 않는다.
- 사용량 확인 때문에 다른 앱, 브라우저 또는 제공자 CLI를 상시 실행해 두지 않는다.
- 비교 결과에는 앱이 발생시킨 보조 프로세스와 수집 과정의 비용을 포함한다.

### 인증과 개인정보

사용자가 이미 로그인한 공식 도구의 인증을 합법적이고 명시적인 경로로 재사용할 수 있는지부터 검증한다. 공용 인증 파일을 무단으로 갱신하거나 덮어쓰지 않는다. 새로 저장해야 하는 비밀은 macOS Keychain 사용을 원칙으로 검토한다.

진단 로그와 벤치마크 자료에는 토큰, 쿠키, 계정 식별자, 프롬프트 또는 대화 내용을 남기지 않는다. 상세 패널에는 표시용 사용량 스냅샷만 전달한다. 자체 서버나 계정 가입은 MVP에 필요하지 않도록 설계한다.

## RAM 비교를 제품 목표에 포함하는 이유

이 앱은 사용자가 직접 조작하는 시간보다 켜 둔 시간이 길다. 패널의 첫 렌더링 속도만으로 품질을 평가할 수 없다. **실제로 사용한 뒤 패널을 닫아 둔 상태의 메모리와 장시간 상주 비용**을 주요 판단 기준으로 삼는다.

CodexBar와 제공자 구성이 같은 조건에서 비교하고, Claude 전용 앱과는 Claude만 켠 조건을 따로 만든다. 비교 앱의 구현 언어만 보고 성능을 예상하거나 서로 다른 계정·서비스 수의 결과를 하나의 순위표로 만들지 않는다. 수치 목표는 첫 기준 측정 후 확정하며, 현재는 측정된 절감률이나 보장 RAM 상한이 없다.

## 범위에서 제외하는 것

- Windows 및 Linux 이식, 플랫폼 공통 UI 추상화를 위한 선행 개발
- 프롬프트 작성·전송, 대화 클라이언트, 에이전트 실행
- 구독 자동 결제·업그레이드·전환
- API 비용을 구독 잔여량으로 추정해 합산하는 기능
- 계정 우회, 인증 제한 우회, 토큰을 외부 서버로 전달하는 수집 방식
- 항상 실행되는 브라우저 자동화 또는 무거운 수집용 보조 앱
- MVP 단계의 다중 계정 관리, 클라우드 동기화, 분석 대시보드

## 완료를 판단하는 기준

앱이 켜지고 숫자가 보이는 것만으로 MVP를 완료하지 않는다. 지원한다고 표시한 제공자는 실제 계정에서 인증·데이터 의미·만료·오류 상태를 확인해야 한다. 패널을 반복해서 열고 닫거나 오랫동안 실행해도 자원이 계속 증가하지 않아야 하며, 같은 조건의 다른 앱과 비교한 결과를 공개해야 한다.

구체적인 단계별 기준은 [로드맵](roadmap.md), 측정 방법은 [성능 계획](performance.md)을 따른다.
