# 로드맵

상태: 공통 데이터 계층 첫 구현 · 갱신일: 2026-10-29

이 문서는 작업 순서와 완료 조건이다. 체크하지 않은 항목은 구현·검증되지 않았다. 네 제공자는 제품 목표이며, 각 제공자의 실제 지원 여부는 별도의 검증 결과로 공개한다.

## 0. 범위와 계획

- [x] 프로젝트 이름을 `light-usage-bar`, 앱 이름을 Light Usage Bar로 정한다.
- [x] macOS 전용, Rust + GPUI, 적은 상주 비용을 핵심 목표로 정한다.
- [x] Claude·Codex·Grok Bot·Antigravity의 제공자 검증 계획을 문서화한다.
- [x] 다른 사용량 앱과의 RAM 비교 계획과 기록 양식을 만든다.
- [x] 첫 측정용 Mac의 모델, RAM, macOS 버전과 측정 도구를 기록한다. [확인한 환경](performance.md#확인한-측정-환경)에 있으며 앱 성능 수치는 아직 없다.
- [ ] 코드 공개에 적용할 라이선스를 정한다.

## 1. 제공자 접근 가능성 검증

UI를 크게 만들기 전에 읽기 전용 수집이 가능한지 확인한다. 특히 Grok Bot의 실제 인증과 Antigravity의 앱 종료 상태에서의 조회 가능성을 일찍 검증해 일정 위험을 드러낸다.

- [ ] Claude: 기존 인증을 사용한 조회, 한도 구간과 초기화 필드를 실제 계정 화면과 대조한다.
- [ ] Codex: 실시간 구독 조회와 로컬 기록을 구분하고, 인증 만료 및 오래된 데이터 상태를 확인한다.
- [ ] Grok Bot: 실제 계정으로 연결 및 `bot.usage` 조회를 검증하고 Bot 구독의 범위를 확인한다.
- [ ] Antigravity: 앱 실행·종료 상태의 수집 경로, 인증 실패, 수집이 발생시키는 프로세스와 비용을 확인한다.
- [ ] 응답 샘플에서 비밀과 계정 정보를 제거해 재현 가능한 파서 검증용 자료를 만든다.
- [ ] 제공자별 `검증 완료 / 조건부 가능 / 차단됨` 결과와 근거를 기록한다.

**완료 조건:** 적어도 Claude와 Codex에서 실제 값의 의미를 검증하고, Grok Bot과 Antigravity의 다음 구현 단계 또는 차단 원인을 구체적으로 기록한다. 지원 여부를 모르는 제공자를 지원 완료로 표시하지 않는다.

## 2. 네이티브 메뉴 막대와 UI 수명 비교

- [ ] 검증할 Rust·GPUI 버전을 고정하고 macOS에서 빌드 가능한 최소 워크스페이스를 만든다.
- [ ] Rust에서 네이티브 메뉴 막대 항목과 이벤트 처리를 구현한다.
- [ ] 같은 표시 데이터로 GPUI 창을 필요할 때 만드는 단일 프로세스 후보를 만든다.
- [ ] 같은 표시 데이터로 종료 가능한 GPUI 패널 보조 프로세스 후보를 만든다.
- [ ] 첫 실행, 첫 표시, 닫은 뒤, 반복 표시 이후의 RAM·CPU·열기 지연을 비교한다.
- [ ] 복수 패널 생성, 빠른 연속 클릭, 포커스 이동, 종료 및 자식 프로세스 정리를 확인한다.
- [ ] 측정 결과로 [결정 기록](decisions/0001-ui-process-lifecycle.md)을 갱신한다.

**완료 조건:** 패널을 닫은 뒤의 전체 비용과 다시 여는 경험을 함께 설명할 수 있다. 별도 프로세스가 실제로 유리한지 모르는 상태에서 구조를 확정하지 않는다.

## 3. 사용량 데이터와 백그라운드 수집

- [x] 한도 구간, 단위, 사용·잔여 방향, 초기화 시각, 출처, 최신성, 오류를 표현하는 공통 모델을 구현한다.
- [ ] 캐시 표시와 네트워크 갱신을 분리한다. 메모리 캐시의 마지막 성공 값과 조회 상태는 분리했으며, 실제 네트워크 연결은 남아 있다.
- [ ] 느린 백그라운드 갱신, 수동 갱신, 요청 합치기, 타임아웃, 취소와 실패 시 간격 증가를 구현한다.
- [ ] 비활성 제공자 무작업, 절전 및 복귀, 네트워크 복구를 처리한다.
- [ ] 검증된 Claude·Codex 경로를 통합한다.
- [ ] 검증 조건을 충족한 Grok Bot·Antigravity 경로를 통합한다.
- [ ] 인증 만료, 일부 필드 없음, 변경된 응답 형식, 이전 캐시 유지 동작을 검증한다.

**완료 조건:** 조회 실패가 앱 전체를 막지 않고, 누락된 값과 오래된 값이 사용자에게 정확히 드러난다. 알 수 없는 값을 0%로 만드는 경로가 없다.

첫 구현은 실제 계정이나 UI 없이 검증할 수 있는 공통 모델과 캐시로 한정했다. 합성 데이터로 실패 후 값 보존, 계정·workspace 전환, 이전 요청 응답 차단, 요청 합치기와 만료 경계를 확인한다. 단계 1의 실계정 검증과 단계 2의 macOS 수명 비교는 아직 수행하지 않았다. 검증 명령과 환경은 [개발 및 검증](development.md)에 기록한다.

## 4. MVP 사용자 경험

- [ ] 메뉴 막대 항목 하나와 제공자별 상세 행을 구현한다.
- [ ] 실제 응답에 맞게 한도 구간, 모델군, 초기화 시점, 마지막 조회 시간을 표시한다.
- [ ] 제공자 켜기·끄기, 수동 갱신, 인증 안내, 앱 종료를 제공한다.
- [ ] 패널이 닫히면 관련 렌더링·타이머·이벤트 감시가 정리되는지 확인한다.
- [ ] 키보드 조작, VoiceOver, 밝은·어두운 모드, 화면 배율을 점검한다.

**완료 조건:** 지원된 서비스의 상태를 짧게 확인할 수 있고, 조회 불가 원인과 마지막 유효 값을 구분할 수 있다.

## 5. 실제 앱과 RAM 비교

- [ ] [성능 계획](performance.md)에 따라 같은 Mac에서 CodexBar의 기준값을 측정한다.
- [ ] Light Usage Bar와 지원 제공자 및 갱신 조건을 맞춘 비교를 수행한다.
- [ ] Claude만 켠 조건에서 claudebar를 비교한다.
- [ ] 설치 및 제공자 조건을 맞출 수 있는 Aura와 ai-usagebar를 추가 비교한다.
- [ ] 앱별 버전·커밋, 주 프로세스와 보조 프로세스, 각 상태의 메모리와 CPU를 기록한다.
- [ ] 반복 열기·닫기와 장시간 실행 이후 증가 추세를 확인한다.
- [ ] 배터리 사용, 유휴 상태의 깨우기와 네트워크 요청 수를 함께 평가한다.
- [ ] 실제 수치와 재현 절차를 [벤치마크 기록](benchmarks.md)에 공개한다.
- [ ] 결과를 바탕으로 RAM 목표와 회귀 허용 범위를 정한다.

**완료 조건:** 측정하지 않은 절감률을 홍보하지 않는다. 비교 조건 차이를 설명하고, 기대보다 무거운 경우 원인과 개선 작업을 기록한다.

## 6. macOS 배포 준비

- [ ] 검증한 최소 macOS 버전과 지원 CPU 아키텍처를 공개한다.
- [ ] 앱 번들, 종료·재시작·업데이트 시 보조 프로세스 수명을 정리한다.
- [ ] 필요한 서명, 공증, 권한과 배포 경로를 결정하고 검증한다.
- [ ] 비밀이 포함되지 않는 오류 보고 방법과 개인정보 설명을 작성한다.
- [ ] 설치 방법, 현재 지원 상태, 알려진 제한, 벤치마크 조건을 README에 반영한다.

**완료 조건:** 사용자가 설치 가능한 산출물과 검증된 지원 범위가 일치한다. Intel Mac은 실측 및 기능 검증 이후에만 지원 목록에 추가한다. Windows 작업은 이 로드맵에 포함하지 않는다.

## 일정 운영

현재는 완료 날짜를 약속하지 않는다. 내부 엔드포인트, 기존 인증의 재사용 가능성, 실제 Mac에서의 자원 측정에 따라 다음 작업을 정한다. 기술 검증 결과가 바뀌면 구현 코드보다 먼저 제공자 상태와 결정 기록을 갱신한다.
