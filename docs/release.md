# 0.1.0 배포 후보 상태

갱신일은 2026-10-30이다. 공개된 릴리스 산출물은 아직 없다. 아래 결과는 관찰한 계정과 환경에 한정한다.

## 대상과 배포 방식

| 항목 | 현재 상태 |
| --- | --- |
| 버전 | `0.1.0` 후보 |
| CPU | Apple Silicon `arm64`. Intel 미지원 |
| 최소 OS | 패키지 설정은 macOS `26.0`. 컴파일 확인 환경은 `26.6.2`, 추가 화면 확인 환경은 `27.0.1` |
| UI | 메뉴 막대 그래프 아이콘, 제공자별 동작 메뉴와 420×560포인트 사용량 카드 패널 구현 |

| 라이선스 | 소유자 선택 전 |

## 현재 검증 결과

M3 Pro MacBook Pro, RAM 18 GiB, macOS 26.6.2, Xcode 26.5에서 전체 워크스페이스 테스트 107개를 통과했다. 고지 4개, 호스트 8개, 공통 모델 18개, 표시 8개, 패널 18개, 제공자 39개, 파싱 6개와 서비스 6개다. 전체 대상의 엄격한 Clippy, release 패키징과 번들 서명 검사도 통과했다. 이 결과는 새 PR의 CI 성공을 뜻하지 않는다.

Claude production 수집기는 M4 Mac mini, macOS 27.0.1의 GUI 세션에서 준비와 조회가 성공했다. 두 구간 모두 측정값과 기간이 있었으며 초기화 시점은 없었다. 진단 뒤 필터링한 프로세스 목록에 probe와 공식 CLI `2.1.312`가 남지 않았다. 검증한 probe의 SHA-256은 `08f65f4df3ab8b5d75db615c31d81c735a8fda6457b1e633415e205aea815bd1`이다. 개인 사용량과 계정 정보는 공개하지 않았다.

이 결과는 해당 GUI 세션과 프로필에 한정한다. 이전 SSH prototype의 인증 필요 결과와 GUI prototype의 구간 표시는 실행 환경이 달랐던 과거 관찰이다. 공식 CLI 로그인만으로 다른 실행 환경의 인증 상태를 보장하지 않는다. 앱의 `5h`와 `7d` 수치를 공식 화면과 대조하는 작업은 남아 있다. 모호한 초기화 시점은 추정하지 않는다.

Mac 네이티브 수명 주기 테스트 8개는 프로세스 그룹과 관찰한 자손의 부재, runtime 종료 전 취소 정리를 포함한다. Darwin에서 출력 제한 후 PTY를 비우지 않아 `yes` 종료 대기가 멈추던 문제는 자식 회수 전에 PTY master를 닫아 수정했다. 출력 제한 테스트도 통과했다. 수집 예산은 45초이며 그 뒤 정리를 기다린다. 전체 실행 시간의 상한이나 모든 형태의 이탈한 자손 회수를 보장하지 않는다.

Claude는 공식 CLI의 `/usage`만 수집한다. 앱은 인증 파일, Keychain helper와 OAuth HTTP fallback을 사용하지 않는다. 관찰마다 계정 미확인 상태를 **Details**에 전달하는 동작은 단위 테스트로 확인했다. 새 앱 화면의 실제 문구 확인은 남아 있다.

Codex와 Grok Bot의 읽기 전용 실계정 조회는 MacBook Pro에서 성공했다. Codex에서는 7일 구간 하나를 확인했다. Grok에서는 서버 사용자 일치와 `bot.usage` 성공을 확인했다. 응답에 사용률 필드가 없어 `Unknown`으로 보존한다. 이 결과는 다른 플랜이나 조직의 지원을 뜻하지 않는다.

Antigravity 2.24.0은 `GetUserStatus`에 email이 없어 `NeedsVerification`을 반환했다. 앱 종료 시 `TemporarilyUnavailable`도 확인했다. 실제 quota 조회 성공은 미검증이다. Mini에는 Antigravity 앱이 없어 그 환경에서는 검사하지 않았다. 계정을 추정하거나 identity 확인을 생략하지 않는다. 연결 경계와 한계는 [제공자 참조](providers.md)에 있다.

## 화면과 조작 검증

패널은 Claude의 `5h`와 `7d`를 별도 행으로 표시한다. 구간이 없으면 `Usage unavailable`을 표시한다. 모델별 주간 구간으로 계정 전체 `7d`를 대신하지 않는다. Codex의 기본 구간 이름은 실제 응답 기간을 따른다. 알 수 없는 사용량은 0% 막대로 표시하지 않는다. Demo는 화면과 **Details**에 `Synthetic demo data`를 표시한다.

이전 할당량 표시 후보 `bb810`의 Mac mini 일반 모드 사용자 캡처에서 Claude 두 행, Codex 기간과 막대, 네 카드와 고정 하단 버튼을 확인했다. 해당 후보는 Mac 테스트 92개와 패키징을 통과했고 ZIP SHA-256은 `c9aceaf245e83719b93b84be627123e6eb91db53eef7dfd8b946187263faf066`이다. 이 후보의 화면은 새 CLI 수집기나 공식 화면의 수치 대조 근거가 아니다.

CLI 전환 뒤 Mini 일반 모드의 새 앱을 사용자가 캡처했다. Claude의 `Up to date`, `5h`와 `7d` 숫자 및 막대, `Reset time unknown`을 확인했다. Codex의 `7d` 막대와 `Stale reading`, Grok의 로그인 필요 상태도 보였다. Antigravity는 카드 머리글만 보였고 나머지는 목록을 스크롤해야 한다. 하단의 전체 갱신, 닫기와 종료 버튼은 고정 영역에 보였다. 개인 사용량 숫자는 기록하지 않는다. 이 캡처는 Details나 버튼 동작, 공식 계정 화면과의 수치 대조를 입증하지 않는다.

이전 CI 번들은 첫 프레임 응답에 성공해도 모든 글자가 빠졌다. GPUI 0.2.2에서 `font-kit`을 켠 수정으로 글자 표시를 확인했다. 첫 프레임 응답만으로 실제 화면 표시를 판정하지 않는다.

## 미리보기 제한

제공자별 조회 성공 범위는 [제공자 참조](providers.md)에 한정한다. 네 제공자 전체 지원을 광고하지 않는다. 공식 계정 화면 대조와 만료 상태 검증은 별도 작업이다.

기본 갱신은 600초다. 성공 값은 Claude에서 600초, 다른 제공자에서 120초가 지나면 오래된 값으로 구분한다. 공식 도구의 로그인 갱신, 자동 업데이트와 다중 계정 UI는 없다.

MacBook Pro 한 대에서 패널을 열지 않은 4시간 대기 관찰 1건을 완료했다. 50회 패널 반복, 패널 사용 후 상주 실험과 다른 앱과의 비교는 남아 있다. RAM, CPU와 에너지 우위는 주장하지 않는다. 별도 단일 프로세스 prototype의 첫 프레임 smoke는 전체 기능 동등성이나 성능 비교 결과가 아니다. 재현 절차는 [성능 계획](performance.md), 결과는 [벤치마크 기록](benchmarks.md)에 있다.

## 빌드와 릴리스 자동화

`macOS application` workflow는 macOS 26 ARM64에서 테스트, Clippy와 패키징을 수행하고 ZIP과 checksum을 artifact로 올린다. 이전 커밋 `6b0bf8ce`의 [CI 실행 40995007697](https://github.com/ColdTbrew/light-usage-bar/actions/runs/40995007697)은 성공했다. 할당량 표시와 Claude CLI 수집 변경은 이 실행에 포함되지 않는다. 새 PR의 CI는 남아 있다.

`Prepare draft release`는 main에서 수동 실행하며 같은 커밋의 성공한 CI 실행 번호를 받는다. 원본 저장소, 커밋, workflow 경로, 실행 종류와 checksum을 확인한 뒤 릴리스 초안을 만든다. 이 흐름의 실제 실행은 아직 확인하지 않았다.

앱 Resources에는 도달 가능한 의존성의 고지와 출처를 포함한다. 배포 crate에 빠진 고지는 upstream 선언, 배포 manifest와 원문으로 보충하고 SHA-256으로 검증한다. 반복 패키징 때 오래된 리소스가 남지 않고 최종 복사본의 서명이 유효한 것도 Mac에서 확인했다. 별도 라이선스 인증을 뜻하지 않는다.
