# 0.1.0 배포 후보 상태

갱신일은 2026-10-30이다. 이 문서는 배포 준비의 확인 결과다. 릴리스 발표문이 아니다. 공개된 릴리스 산출물은 아직 없다.

## 대상과 배포 방식

| 항목 | 현재 상태 |
| --- | --- |
| 버전 | `0.1.0` 후보 |
| CPU | Apple Silicon `arm64`. Intel 미지원 |
| 최소 OS | 패키지 설정은 macOS `26.0`. 실제 컴파일 확인 환경은 `26.6.2` |
| UI | AppKit 메뉴와 별도 GPUI `0.2.2` 패널 구현 |
| 패키지 | Mac에서 앱 번들·ZIP·SHA-256 생성과 서명 검증 통과. UI 실행 확인 전 |
| 서명 | 기본 ad hoc. Developer ID 미확인 |
| 공증 | 미수행. 패키징 스크립트에 공증 단계 없음 |
| 배포 | 공개 업로드 전 |
| 라이선스 | 소유자 선택 전 |

## 확인한 근거

컴파일 환경은 M3 Pro MacBook Pro, RAM 18 GiB, macOS 26.6.2, Xcode 26.5다. `DEVELOPER_DIR`로 전체 Xcode를 선택했다. 기본 Metal toolchain을 다운로드한 뒤 GPUI를 포함한 워크스페이스 실행 파일 컴파일이 통과했다.

실계정 읽기 전용 조회는 Codex와 Grok Bot에서 성공했다. Codex에서는 7일 구간 하나를 확인했다. Grok에서는 서버 사용자 일치와 `bot.usage` 성공을 확인했다. Grok 응답에 사용률 필드가 없어 사용률은 `Unknown`으로 보존한다. 개인 사용량 숫자는 공개하지 않는다.

Claude는 비대화형 SSH에서 Keychain `PermissionDenied`를 반환했다. 사용량 조회 성공은 확인하지 않았다. 사용자 지정 Claude 프로필에 인증 파일이 없을 때 전역 Keychain으로 넘어가지 않도록 구현했다. Keychain helper에는 2초 제한과 취소 시 종료 및 회수 경로가 있다.

Antigravity는 파서만 있다. 조회 전송 경로가 없어 `NeedsVerification`을 반환한다. 관찰 환경에서 Antigravity 앱은 실행되지 않았다.

## 아직 통과하지 않은 확인 항목

아래 항목은 미리보기 배포 전에 확인하거나 배포 제한으로 명시해야 한다. 체크하지 않은 항목을 통과로 해석하지 않는다. 전체 로드맵의 성능 비교 완료를 0.1.0 미리보기의 조건으로 삼지는 않는다.

- [ ] GPUI 패널이 실제 표시되고 준비 응답을 보내는 smoke test.
- [ ] 네이티브 메뉴와 패널에서 갱신, 활성화 변경, 인증 안내와 종료 조작.
- [ ] Escape, 바깥 클릭, 빠른 재개방, 패널 중복 실행과 자식 프로세스 정리.
- [ ] 복수 화면과 화면 배율, 키보드 조작, VoiceOver, 밝은 모드와 어두운 모드.
- [ ] sleep과 wake, offline, timeout, 인증 만료와 rate limit 시나리오.
- [x] 실제 release 앱 번들 생성, ad hoc 서명과 ZIP checksum 검증.
- [ ] 설치 후 실제 화면에서 실행.
- [ ] Developer ID 서명, 공증, stapling과 Gatekeeper 확인 또는 미리보기 배포 제한 명시.
- [ ] 공개할 릴리스 파일과 checksum 업로드 및 실제 다운로드 확인.
- [ ] 소유자의 라이선스 선택.

현재 smoke 실행은 잠긴 Mac 화면에서 이루어졌다. 네이티브 창은 관찰했지만 GPUI 준비 응답은 확인하지 못했다. 잠금 상태의 결과만으로 앱 시작 결함이나 정상 표시를 판정할 수 없다. 잠금 해제 후 재실행이 필요하다. 패널 종료 응답 확인, 제공자별 element ID 분리와 NSScreen 기반 화면 배치 수정은 반영했지만 실제 UI 조작 검증은 남아 있다. macOS 전체 동작 테스트 55개와 엄격한 Clippy가 통과했다. 패키징 도구 테스트 4개도 Mac에서 통과했다.

## 미리보기에서 설명할 제한

제공자별 조회 성공 범위는 [제공자 참조](providers.md)에 한정한다. 네 제공자 전체 지원을 광고하지 않는다. 사용량 정확성의 계정 화면 대조와 만료 상태 검증은 별도 작업이다.

기본 갱신은 600초이고 성공 값의 신선도는 120초다. 오류와 오래된 값을 구분한다. 공식 도구의 로그인 갱신, 자동 업데이트와 다중 계정 UI는 없다.

50회 패널 반복과 4시간 상주 실험, 다른 앱과의 비교는 후속 성능 검증 계획이다. RAM, CPU와 에너지 비교 결과는 아직 없다. 별도 패널 구조가 다른 앱이나 단일 프로세스보다 효율적이라는 주장은 하지 않는다. 재현 절차는 [성능 계획](performance.md), 결과는 [벤치마크 기록](benchmarks.md)에 둔다.

## 빌드 및 릴리스 자동화

`macOS application` workflow는 macOS 26 ARM64에서 테스트·Clippy·패키징을 수행하고 ZIP과 체크섬을 artifact로 올린다. `Prepare draft release`는 main에서 수동 실행하며, 같은 커밋의 성공한 CI 실행 번호를 받는다. 원본 저장소, 커밋, workflow 경로, push 또는 수동 실행 여부와 체크섬을 확인한 뒤 미리보기 릴리스 초안을 생성한다. GitHub에서 이 흐름이 실제 실행된 결과는 아직 확인 전이다.

앱 Resources에는 도달 가능한 의존성 489개의 고지와 출처를 포함했다. 배포 crate에 누락된 40개 패키지는 정확한 upstream 선언이나 배포 manifest 및 참조 원문으로 보충했다. 보충 파일 85개는 SHA-256으로 검증한다. 반복 패키징 때 오래된 리소스가 남지 않고 최종 복사본의 서명이 유효한 것도 Mac에서 확인했다. 이는 원문 고지 수집 결과이며 별도 라이선스 인증을 의미하지 않는다.
